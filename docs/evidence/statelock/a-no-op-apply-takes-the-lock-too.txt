So an apply with nothing to do DOES take the lock. It has to: the lock is acquired before
the state is read, so terraform cannot yet know there is nothing to do.

This corrects what this repository said until 28-8-2026, which was that a no-op apply
takes no lock at all. That came from running two no-op applies at once, seeing both
succeed, and sampling pg_locks at human speed and finding it empty. Both observations
were real and the conclusion was wrong: a no-op apply holds the lock for a fraction of a
second, so two of them usually miss each other and a coarse sample usually misses it.
A near miss is not an absence, and an absence is not a mechanism.
